# ✉️ HITS Chatbot API

FastAPI backend for the HITS RAG chatbot.

This package exposes the chatbot through HTTP endpoints and integrates the `chatbot_orchestrator` service into a web API. It is the main entry point for external clients such as frontend applications, scripts, or other backend services.

## Responsibilities

- Expose REST endpoints for chatbot interaction
- Validate request and response payloads
- Initialize and inject the `ChatService`
- Configure startup lifecycle behavior
- Optionally enable telemetry and observability hooks

## Main Components

### `main.py`
Defines the FastAPI application and its lifespan.

At startup, the app:

- loads telemetry if enabled
- builds the chatbot service
- stores it in `app.state.chat_service`

### `routes.py`
Defines the public API routes and schemas.

Current endpoints:

- `POST /chat`
- `GET /liveness`

### `wiring.py`
Contains the dependency wiring logic required to build the `ChatService`.

This is where the API layer connects configuration and infrastructure to the orchestrator package.

### `config.py`
Defines API-specific settings using Pydantic settings.

### `telemetry.py`
Contains optional telemetry initialization logic.

## Endpoints

### `POST /chat`

Send a message to the chatbot.

#### Request body

```json
{
  "message": "What is Python?",
  "thread_id": "user-123"
}
```

#### Response

```json
{
  "response": "Python is a programming language created by Guido van Rossum.",
  "thread_id": "user-123"
}
```

#### Notes

- `message` must be a non-empty string
- `thread_id` identifies the conversation thread
- the response is generated by the underlying `ChatService`

---

### `GET /liveness`

Simple health check endpoint.

#### Response

```json
{
  "message": "OK"
}
```

## Running Locally

From the repository root:

```bash
(export $(cat envs/.env.dev | xargs) && uv run --package api uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload)
```

It is important to export the developement environment before launching the webserver because all the configuration is propagated top-down from the API package.

By default, the app will be available at:

```text
http://127.0.0.1:8000
```

With SwaggerUI documentaions at:

```text
http://127.0.0.1:8000/docs
```

You can then test it with:

```bash
curl -X POST "http://127.0.0.1:8000/chat" \
  -H "Content-Type: application/json" \
  -d '{"message":"Hello","thread_id":"test-thread"}'
```

Or just use postman with the right parameters.

Or check liveness:

```bash
curl http://127.0.0.1:8000/liveness
```

## Configuration

This package reads configuration from environment variables via Pydantic settings.

Configuration is split between:

- shared/core settings from `packages/core`
- API-specific settings from `packages/api`

Typical configuration includes:

- telemetry enablement
- model provider configuration
- vector database settings
- persistence backend settings

In development, tests and local runs may use `.env.dev`.

## How It Works

The API package does not implement chatbot logic directly.

Instead:

1. FastAPI receives the HTTP request
2. the route validates the request body
3. the route obtains a `ChatService`
4. `ChatService` delegates to the LangGraph orchestration layer in `chatbot_orchestrator`
5. the final answer is returned as a JSON response

This separation keeps the API layer thin and focused on transport concerns.

## Additional Toools

### Adding users to the DB

Considering that the service does not need to manage users in runtime, all the users that should be able to access the chatbot should be defined explicitely after the initialization of the database (it is sufficient to launch the api one time to do so).

To create the users create a file like `users.json`, formatted in this way:
```json
[
  {
    "username": "alice",
    "password": "temporary-password-1"
  },
  {
    "username": "bob",
    "password": "temporary-password-2"
  }
]
```

Then call the tool with this command:
```bash
(export $(cat envs/<envfile> | xargs) && uv run python -m api.tools.add_users --database-url "<db_url>"   --users-file "./users.json")
```

Be sure to have the correct relative path when writing the location of the user file, otherwise you can use an absolute path to be sure.

## Development Notes

### Lifespan initialization

The application uses a FastAPI lifespan hook to initialize the chatbot service on startup.

This means:

- the app service is created once at startup
- it is attached to `app.state`
- routes retrieve it through dependency injection

### Dependency injection

The `ChatService` is accessed through a dependency function in `routes.py`, which makes it easier to override in tests.

## Example Test Client Override

In tests, the service can be overridden with a fake implementation:

```python
from api.routes import get_service

class FakeChatService:
    async def ainvoke(self, message: str, thread_id: str):
        return f"Echo: {message}"

app.dependency_overrides[get_service] = lambda: FakeChatService()
```

This avoids initializing or calling real LLM infrastructure during endpoint tests.
